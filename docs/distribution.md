# Distribution

Releases are published on GitHub (latest: v0.3.2, 2026-11-09) as SHA-256-checked archives for Linux x64 and aarch64, macOS Intel and Apple Silicon, and Windows x64. No package is code-signed or notarised and update manifests are not signed. `packaging/linux/build-deb.sh` builds an unsigned Debian package (`target/deb/tehom_<version>_<arch>.deb`) with both binaries, a desktop entry, the logo recoloured only (geometry verified identical), licences and example configuration. It declares FFmpeg, yt-dlp and GStreamer base/good/libav as dependencies rather than bundling them. It has been built and inspected on Arch Linux but not installed on Debian or Ubuntu. One-command installers: `install.sh` (Linux and macOS: `curl -fsSL https://raw.githubusercontent.com/OnurByte/Tehom/main/install.sh | sh`) and `install.ps1` (Windows: `irm …/install.ps1 | iex`). They download `tehom-<os>-<arch>` archives from GitHub Releases, verify SHA-256, install for the current user only (`~/.local/bin` with a desktop entry, `~/Applications/Tehom.app`, or `%LOCALAPPDATA%\Programs\Tehom` with PATH and a Start menu shortcut) and offer, after asking, to install FFmpeg and yt-dlp, plus GStreamer on Linux and macOS. `.github/workflows/release.yml` builds those archives on `v*` tags with `packaging/release-archive.sh` and smoke-tests each packed CLI. Updates: `tehom update` (and Settings, then Install update) runs the installer published with the latest release tag into the folder of the running binaries; the replaced binaries are kept in `.tehom-previous` and `tehom update --rollback` restores them, renaming a running binary aside so it also works on Windows. The desktop checks GitHub at start unless "Check at start" is off. Evidence on 2026-11-07: `tehom update --check` against GitHub reported 0.2.1 as current; the local installer kept the replaced binaries and `tehom update --rollback` restored them. A full live update needs a release that already contains the new installer, so it can first be exercised from v0.3.0 onwards; no live update between published releases is recorded yet. Earlier evidence on 2026-11-07: `install.sh` piped through `sh` into an isolated HOME installed both binaries, the desktop entry and icon, reported missing GStreamer plug-ins, and refused a tampered checksum without installing; `install.ps1` was not run (no PowerShell on the test host).

Windows: `packaging/release-archive.sh` puts the GStreamer 1.28.8 DLLs the desktop and a fixed plug-in list import, `gst-plugin-scanner.exe` and the Visual C++ runtime beside the binaries, so the zip starts without any GStreamer installed and application-local DLLs win over another GStreamer on PATH. `install.ps1` no longer installs GStreamer; it replaces DLLs file by file, moving ones in use to `.tehom-old`. The release workflow runs the packed `tehom.exe --version` and `tehom-desktop.exe --check-preview` on a real MP4 with only Windows on PATH. Evidence on 2026-11-09: Release run 42624134054 packed a 35 MB zip with 64 DLLs on windows-2025 and both checks passed with only Windows on PATH; Release run 42629411841 repeated them at `625f405` and published v0.3.2. That runner still has the Visual C++ runtime and other system files, and the updated `install.ps1` has not been run on a real Windows computer.

The native-prototype CI builds Linux x64, Windows x64 and both macOS architectures, runs real-media tests and captures native windows. Artifacts are development evidence, not signed distributable packages. Inspect screenshots and logs before recording the preview gate as passed.

Release work after the gate must provide user-scope, integrity/signature-checked installation, versioned updates and rollback; deb, Flatpak, dmg and Windows exe; runtime bundling and license notices; real clean-install/uninstall checks. AppImage and web shells remain excluded.
