# Security boundaries

Channel inputs accept only validated YouTube channel IDs or HTTPS YouTube channel/handle URLs. Credentials, explicit ports, unrelated/private hosts and path-normalization tricks are rejected. RSS endpoints are fixed by the application; response sizes, redirects and timeouts are controlled. Local AI endpoints are restricted to loopback, disable proxy inheritance and redirects, and accept no embedded credentials. Updates contact `api.github.com` (latest release of this repository only) and `raw.githubusercontent.com` (the installer script pinned to the release tag), and only when the user checks or the desktop starts with "Check at start" on. Installing runs that release's installer, which verifies the archive's SHA-256 and keeps the replaced binaries in `.tehom-previous` for `tehom update --rollback`. Releases are not code-signed yet.

Remote AI is opt-in (BYOK):
- **Consent:** choosing OpenAI, Anthropic, Gemini, OpenRouter, Codex or Claude Code needs explicit consent (`--consent`, `remote_consent = true` or the desktop "Allow and use" button), and the engine refuses to send captions without it. Only captions are sent; videos never leave the computer.
- **Keys:** keys are read from the provider's environment variable or the OS keyring (macOS Keychain, Windows Credential Manager, Linux Secret Service). They are never written to SQLite, logs or command lines, and `tehom ai-key` reads them from stdin.
- **Hosts:** each API provider may reach only its fixed HTTPS host. Model names are checked so they cannot change the request path.
- **CLI providers:** the signed-in Codex and Claude Code CLIs run with argument arrays, the transcript on stdin and an empty temporary working folder. Claude Code runs with no tools. Codex runs in its read-only sandbox, which can still read files on the computer, so a hostile transcript could try to make it reveal local data in its answer. Prefer an API provider or Claude Code for untrusted channels. Every engine HTTP request passes one outbound allowlist: `https://www.youtube.com` without credentials or ports, and loopback hosts. Social and publishing APIs are refused before any connection is made. yt-dlp runs as a separate process and performs its own YouTube downloads outside this client. Adding Kick support requires an explicit allowlist change.

FFmpeg, ffprobe and yt-dlp receive argument arrays. Local media inspection rejects special files, restricts protocols, bounds subprocess output and supports timeouts/cancellation. Completed MP4 publication uses secure temporary files and no-clobber semantics. Automatic exports include a persisted random ownership identity; interrupted publication is adopted only after identity, geometry and duration verification, preserving unrelated existing files.

SQLite transactions preserve candidate batches before any render. A lifetime file lock prevents duplicate engine ownership. Cancellation cannot be overwritten by a final completed-state update. Missing transcripts never trigger ASR or arbitrary exports.

Remaining release work includes cloud-provider consent/keyring support, stronger downloader process-tree lifecycle checks on all systems, migration/version policy, signing/update integrity, independent security review and third-party redistribution/license audit. Current CI evidence is not a release security certification.
