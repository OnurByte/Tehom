That host lacks `avdec_h264` (gst-libav) and `autoaudiosink` (gst-plugins-good). This is the missing bundled-runtime gate, not a passed check. A render whose writes are refused part-way (RLIMIT_FSIZE, standing in for a full disk) publishes nothing, leaves no temporary file and keeps existing files byte-identical; a real ENOSPC volume was not used. Invalid channel and video URLs passed to the real `tehom add` binary exit with a clean error (no panic) and persist nothing. Formatting and strict Clippy pass; builds need `-j 2` on that host to avoid compiler OOM kills.

- Engine fixtures exercise SQLite restart/pause/cancellation/dedup, missing model/captions, candidate validation, complete batch persistence, source retention on temporary RSS failure, actual vertical MP4 output through a local HTTP model fixture, ownership-based crash recovery and late subtitle refresh. Fixture success is not live-provider success.

Earlier HTTP 404 errors were retained and reported correctly. The newest real video downloaded and passed ffprobe; missing platform captions stopped it for input without ASR/export. Actual llama.cpp/Qwen 1.5B inference selected three valid 20-second candidates from authored test input; all three exported MP4s passed ffprobe geometry/codec/duration checks. This is not quality evidence on natural long videos. See [local model evidence](evidence/local-model.md).
